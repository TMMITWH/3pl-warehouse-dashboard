# 3PL Warehouse Operations Dashboard

Interactive dashboard for the **Inventory Department Weekly Report** (3PL Warehouse), covering the report types from the weekly Word report:

| # | Report | Dashboard tab |
|---|--------|---------------|
| 1 | Inbound Status — Containers | Inbound — Containers |
| 2 | Inbound Status — LCL | Inbound — LCL |
| 3 | Staff-wise Confirmed Jobs | Staff Confirmed Jobs |
| 4 | Staff-wise Customer Inbound Jobs | Inbound / Outbound Jobs |
| 5 | Staff-wise Customer Outbound Jobs | Inbound / Outbound Jobs |
| 6 | Customer-wise Transaction In & Out | Customer Transactions |

Currently available data: **01.06.2026 – 10.06.2026** (521 transactions: 246 inbound + 275 outbound) — loaded into Supabase, not the repo.

**The raw warehouse Excel exports are the only data source.** The ETL script (`etl/process_report.py`) converts them into transaction-level rows, and the dashboard computes every report view live for any **date period you select** (date-from / date-to filter with Last 7 Days and Full Range presets). All KPIs, charts and tables recalculate instantly when the period changes.

**The data is PRIVATE.** All warehouse data lives only in Supabase, protected by a Row Level Security policy that allows reads **only for signed-in team members** (Supabase Auth, email + password). The dashboard shows a login screen before anything loads. No warehouse data is committed to the GitHub repository: `js/data.js` is an empty stub and `supabase/seed_generated.sql` + `*.xlsx` are gitignored, so the repo and the GitHub Pages site are safe to be public.

The dashboard is a static site (HTML + CSS + JS, Chart.js) — no build step required. It works in two modes:

- **Embedded mode (default):** reads from `js/data.js` (generated by the ETL). Open `index.html` and it just works.
- **Supabase mode (live):** when `js/supabase.js` is configured, all six tables are loaded from your Supabase database.

## 0. Weekly workflow (live update)

```bash
pip install pandas openpyxl requests

# Generate dashboard data + SQL from the raw exports (full files, all dates)
python3 etl/process_report.py \
    --inbound  inbound_for_inventory_report.xlsx \
    --outbound outbound_inventory_report.xlsx

# OR push straight into Supabase (true live update — no SQL editor needed)
export SUPABASE_URL="https://YOUR-PROJECT.supabase.co"
export SUPABASE_SERVICE_KEY="YOUR-SERVICE-ROLE-KEY"   # keep secret, never commit
python3 etl/process_report.py --inbound inbound.xlsx --outbound outbound.xlsx --push
```

What the script does:

- Reads every row (date = `Created On`, staff = `Created By`, volume = `Vol in M3`, customer = `Ship-from` / `Ship-To` + description)
- Classifies **Containers vs LCL** (doc types `Z4FI`/`Z4HI`, ISO container numbers, `CNTR`/`40FT` codes → container; everything else → LCL)
- Writes transaction-level rows to `js/data.js` and `supabase/seed_generated.sql`
- With `--push`, replaces those dates' rows in the `warehouse_transactions` table directly

Period selection now happens **in the dashboard UI**, not in the ETL — load all available days and filter on screen.

For a local preview without Supabase, add `--embed` (writes real data into `js/data.js`) — **never commit that version**; the default run resets it to an empty stub.

### Create team logins

In Supabase: **Authentication → Users → Add user** (email + password, tick auto-confirm) for each team member. There is no public signup. To revoke access, delete the user.

## 2. Set up Supabase

1. Go to [supabase.com](https://supabase.com) and create a new project.
2. Open **SQL Editor** and run, in order:
   - `supabase/schema.sql` — creates the 7 tables with read-only Row Level Security
   - `supabase/seed_generated.sql` — loads the transaction rows (generated by the ETL from the Excel)
3. Go to **Project Settings → API** and copy:
   - **Project URL**
   - **anon (public) key**
4. Paste both into `js/supabase.js`:

```js
window.SUPABASE_CONFIG = {
  url: "https://YOUR-PROJECT.supabase.co",
  anonKey: "YOUR-ANON-KEY"
};
```

The header will show **DATA SOURCE: SUPABASE (LIVE)** when connected. If Supabase is unreachable, the app automatically falls back to the embedded dataset.

> **Security note:** the anon key is safe to commit only because RLS limits it to read-only `select`. Never put the `service_role` key in this repo. To insert next week's data, add a new row to `report_periods` and insert rows referencing its id (via SQL Editor or a server-side script using the service role key).

## Updating with new exports

Run the ETL against the new raw exports (see section 0). With `--push` the
dashboard updates live from Supabase; without it, commit the regenerated
`js/data.js` and push to GitHub. New dates simply extend the range available
in the dashboard's date-period filter.
